# 文档末尾选择文字闪退

2026-10-25，macOS arm64，用户提供的 macOS 笔记。原文档未修改。

## 原因

选中文字会刷新状态栏字数，调用 `selected_markdown_text` →
`cross_block_selected_markdown` → `markdown_chunk_for_block`。
源码映射和文档序列化对空行的处理不一致：

- 两个列表项之间有空段落时，映射额外计算了一次换行。
- 列表项内的非图片段落前，序列化会插入一个空行，映射却没有计算。

因此后续块的绝对字节偏移不断错位。选择末尾文字时，直接切片可能落到
中文 UTF-8 字符内部，或超过整个字符串长度。发布版遇到 panic 会中止进程。
原文档的修复前测试出现 `end byte index 6537 is out of bounds for string of length 6536`；
原生窗口全篇选择也复现了中文字符边界 panic，调用栈经过状态栏字数统计。

## 修复与验证

- 源码映射和序列化共用根块分隔空行及列表子段落空行规则。
- 选区字符串提取使用受检切片；映射无效时直接序列化当前块，避免状态栏渲染中止程序。
- 回归测试覆盖松散列表、列表内段落、中文与 emoji、双向跨块选择、选区文本和删除。
- 原文档所有块的映射已对齐；修复版原生窗口底部拖选、全篇选择均正常。
- `cargo test`：851 通过、0 失败、3 忽略。`cargo fmt --check` 和 `git diff --check` 通过。

本机诊断、修复前后映射结果、崩溃调用栈和构建日志保留在
`/tmp/typers-selection-crash/`。

## 格式化中文链接选区闪退（2026-10-26）

针对 Markdown 格式测试记录 QA-01，进一步得到可稳定复现的最小样本：

```markdown
[**粗体** 与 *斜体* 的链接](https://example.com/formatted)
```

打开后按 Home，再连续两次 Shift＋→。修复前的 GPUI 窗口测试和原生调试窗口均失败：

```text
end byte index 5 is not a char boundary;
it is inside '粗' (bytes 3..6 of string)
```

调用链为 `selected_markdown_text` → `render_status_bar` → 编辑器渲染。原生回调不能展开 Rust panic，进程随之中止。

原因是展开链接的选区映射把“第一个可见文字的源码位置减去左方括号长度”当成整个链接起点。中文前有粗体等标记时，起点本身已经偏移；链接只展开部分格式时，显示文字与规范 Markdown 也不再逐字节相同。直接相加会落入中文 UTF-8 字符中间。

修复内容：

- 按实际片段序列化计算链接起止位置，分别映射标签正文、格式标记以及 URL/title 后缀。输入和输出范围都落到 UTF-8 字符边界；部分展开的标记按对应源码区域映射。
- 单块选区文本使用受检切片，避免异常映射在状态栏中止进程。
- 编辑部分展开的链接标签时使用规范源码保留隐藏的格式，防止输入时丢掉同一链接中未展开的斜体。

新增回归覆盖原查找／快速输入序列、Home＋Shift 方向键触发路径、各种合法字符边界选区、中文标题和 URL 的精确映射、混合格式标签输入与撤销。字符边界测试同时检查光标映射单调性及编辑后的选区有效性。

验证：`cargo test` 874 通过、0 失败、3 忽略；`cargo fmt --check`、`git diff --check` 均通过。Release 构建与 ad-hoc 签名校验成功。已更新 `/Applications/Typers.app`、`dist/Typers.app` 及本地 ZIP，发布镜像 UUID 为 `A8FE8B8B-ABB3-3B4F-ACC9-1938EE130810`。最终安装版已实测相同选区、中文／emoji 输入、保存与撤销，粗体、斜体和 URL 均保留。
